# Pain of Claude Code Alone → How fPM Solves It

* This slide is the deck's **necessity hook** — once you feel "yes, this bothered me too," the rest of the features click naturally
* Claude Code is powerful, but designed on the **assumptions** below. The gap between those assumptions and **real work** is the source of the pain

::: htmlart compare
* **Claude Code alone** / Assumption
  - One session
  - One project
  - One chat window
* **Real work** / Reality
  - Many projects
  - Long-running, repeated
  - Across many windows
:::

---

# Before → After at a Glance

| Situation        | Claude Code alone         | With fPM                    |
| :--------------- | :------------------------ | :-------------------------- |
| Checking results | Scroll / re-search in chat| Render as HTML doc, re-open |
| Long tasks       | Wait until it finishes    | Live progress on dashboard  |
| Project switch   | Memorize path + `cd`      | `cdf 11` instant jump       |
| Dependent work   | Manage order by hand      | Auto-delegate via `depends` |
| Workspace        | Juggle 3 windows          | One VSCode screen           |
| Remote server    | Memorize IP / login       | `sshf gpu1` connect by name |

* The key: fPM **handles the repeated costs of "remember, switch, wait"** for you

# What Fundamentally Changes

::: htmlart arrow
* Evaporates
  - Flows away in chat
* Persists
  - Stays as files/links to re-read and share
* Waiting
  - "When will it finish?"
* Observing
  - Progress in real time
* Memorizing
  - Learn paths and servers
* Pointing
  - One number or name
:::

> fPM isn't a tool of new features to learn — it's a tool that **removes repeated costs so you focus on Claude Code**
