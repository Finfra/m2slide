# 4. htmlArt 23타입 카탈로그

들여쓰기 아웃라인을 타입 선택만으로 구조 도해(SmartArt 대응)로 변환하는 구성요소. 같은 아웃라인을 두고 타입 이름만 바꾸면 다른 도해가 된다. (구 htmlArtTest v0.3.1)

* 문법: `::: htmlart <type>` fenced div + 표준 들여쓰기 리스트
* 타입 분류: v1 4종(process·cycle·hierarchy·pyramid) + v2 10종(timeline·venn·matrix·target·funnel·gear·radial·chevron·step·arrow) + v3 list 5종(numbered·hexagon·bracket·block·tab) + v4 비율·균형 2종(pie·balance) + v5 비교·풀이 2종(compare·explain)
* 빌드 시 `markdown.js preprocessPandocDiv` + 런타임 d3 SVG `htmlart_dispatch`로 렌더

---

## process — 프로세스 체인

* 최상위 항목 = 순차 단계, 작성 순서 = 진행 순서.
* 하위 들여쓰기 = 단계 내부 보조 설명.

::: htmlart process
* 기획
  - 주제·청중 정의
* 설계
  - 목차·장표 구성
* 구현
  - 슬라이드 작성
* 배포
  - 빌드·공유
:::

---

## cycle — 주기 순환

* 최상위 항목 = 순환 노드. 마지막 노드가 첫 노드로 되돌아간다.
* 반복·라이프사이클 표현에 사용.

::: htmlart cycle
* 학습
  - 새 개념 습득
* 적용
  - 실제 작업에 사용
* 피드백
  - 결과 점검
* 개선
  - 다음 주기 반영
:::

---

## hierarchy — 계층 트리

* 들여쓰기 깊이 = 트리 깊이. 최상위 1개 = 루트.
* 조직도·분류 구조 표현에 사용.

::: htmlart hierarchy
* m2slide 구성요소
  - Core
    - 레이아웃
    - 카드
    - htmlArt
  - Visual
    - 심벌
    - 차트
:::

---

## pyramid — 피라미드

* 최상위 항목 = 층(band). 1번째 항목이 꼭대기.
* 비례·우선순위 층 표현에 사용.

::: htmlart pyramid
* 비전
  - 장기 방향
* 전략
  - 중기 계획
* 실행
  - 일상 작업
:::

---

## timeline — 타임라인

* 최상위 항목 = 시점. 작성 순서 = 시간 순서.
* 가로 축선 + 마일스톤 마커 + 상하 교대 라벨.

::: htmlart timeline
* 2023
  - 프로젝트 착수
* 2024
  - 베타 출시
* 2025
  - 정식 버전
* 2026
  - 글로벌 확장
:::

## venn — 벤다이어그램

* 최상위 항목 = 집합(원). 2·3개는 정형 배치, 4개+ 는 선형 벤.
* 중첩·공통점·차이점 표현에 사용.

::: htmlart venn
* 디자인
  - 시각·경험
* 엔지니어링
  - 구현·성능
* 비즈니스
  - 가치·수익
:::

---

## matrix — 사분면 격자

* 최상위 항목 = 사분면(4개 권장). 부족 시 빈칸, 초과 시 절단.
* 2차원 분류·우선순위 매트릭스 표현에 사용.

::: htmlart matrix
* 긴급·중요
  - 즉시 처리
* 비긴급·중요
  - 계획 수립
* 긴급·비중요
  - 위임
* 비긴급·비중요
  - 제거
:::

---

## target — 동심원

* 최상위 항목 = 링. 작성 순서 = 바깥→안.
* 포함·점층·핵심 강조 관계 표현에 사용.

::: htmlart target
* 인지
* 관심
* 욕구
* 행동
:::

---

## funnel — 깔때기

* 최상위 항목 = 단계. 작성 순서 = 위→아래.
* 필터링·수렴·세일즈 퍼널 표현에 사용.

::: htmlart funnel
* 방문자
  - 전체 유입
* 가입자
  - 계정 생성
* 활성 사용자
  - 핵심 기능 사용
* 유료 전환
  - 결제 완료
:::

---

## gear — 톱니바퀴

* 최상위 항목 = 톱니바퀴. 상하 교대 배치로 맞물림을 표현.
* 상호의존·연동 시스템 표현에 사용.

::: htmlart gear
* 데이터
  - 수집·정제
* 모델
  - 학습·추론
* 서비스
  - 배포·운영
:::

---

## radial — 방사형

* 최상위 1번째 = 중심, 나머지 = 스포크.
* 중심 개념 + 관련 요소 표현에 사용.

::: htmlart radial
* m2slide
* 마크다운 파서
* 테마 시스템
* 컴포넌트 훅
* 빌드 파이프라인
:::

---

## chevron — 갈매기형 체인

* 최상위 항목 = 단계. 강한 진행감을 강조.
* 맞물린 갈매기형(>) 화살표 체인.

::: htmlart chevron
* 분석
* 설계
* 개발
* 검증
:::

---

## step — 계단형 단계

* 최상위 항목 = 단계. 1번째가 맨 아래.
* 점진적 상승·성장·레벨업 표현에 사용.

::: htmlart step
* 입문
  - 기초 학습
* 숙련
  - 실전 적용
* 전문
  - 심화·최적화
* 마스터
  - 전수·혁신
:::

---

## arrow — 수렴 화살표

* 최상위 1번째 = 중심(결과), 나머지 = 수렴 입력.
* 여러 입력이 하나의 결과로 모이는 관계 표현에 사용.

::: htmlart arrow
* 통합 인사이트
* 정량 데이터
* 사용자 인터뷰
* 시장 조사
* 경쟁 분석
:::

---

## numbered — 번호 카드 리스트

* 최상위 항목 = 카드, 작성 순서대로 번호 배지가 붙는다.
* 순서 있는 목록·체크리스트·랭킹에 적합.

::: htmlart numbered
* 요구 정의
  - 이해관계자 인터뷰
* 설계
  - 구조·인터페이스 확정
* 구현
  - 코드 작성·리뷰
* 검증
  - 테스트·QA
:::

---

## hexagon — 육각형 리스트

* 최상위 항목 = 육각 노드, 상하 교대(zigzag)로 배치된다.
* 상호 연결된 아이디어 시리즈 표현에 사용.

::: htmlart hexagon
* 탐색
* 정의
* 발상
* 프로토타입
* 테스트
:::

---

## bracket — 괄호 그룹 리스트

* 최상위 = 그룹, 하위 들여쓰기 = 그룹 멤버 (2단 입력).
* 큰 중괄호로 그룹 경계를 강조한다.

::: htmlart bracket
* 프론트엔드
  - 컴포넌트 설계
  - 상태 관리
  - 라우팅
* 백엔드
  - API 설계
  - 데이터베이스
  - 인증
:::

---

## block — 세로 악센트 블록 리스트

* 최상위 항목 = 블록, 좌측 색 악센트 바 + 단일 컬럼 세로 적층.
* 균질 박스 그리드(`::: cards`)와 달리 항상 1열이다.

::: htmlart block
* 데이터 수집
  - 외부 API 연동
* 데이터 정제
  - 결측·이상치 처리
* 데이터 분석
  - 통계·시각화
:::

---

## tab — 탭 그룹 리스트

* 최상위 = 탭 그룹, 하위 들여쓰기 = 탭 내 항목 (2단 입력).
* 정적 렌더 — 모든 탭을 펼쳐 세로로 나열한다.

::: htmlart tab
* 1분기
  - 매출 12억
  - 신규 고객 340
* 2분기
  - 매출 15억
  - 신규 고객 410
* 3분기
  - 매출 18억
  - 신규 고객 470
:::

---

## pie — 부채꼴 비율

* 최상위 항목 = 조각. 라벨 끝 `N%` 또는 ` N` 토큰을 비율로 파싱.
* 비율 없으면 균등 분할. 부분-전체 비율 시각화에 사용.

::: htmlart pie
* 모바일 45%
  - iOS·Android
* 데스크탑 30%
  - Windows·macOS
* 태블릿 15%
* 기타 10%
:::

---

## balance — 양팔 시소

* 최상위 정확히 2개(좌·우). 하위 항목 수 또는 라벨 끝 `N` 숫자 = 가중치.
* 무거운 쪽 팔이 아래로 기울어진다. 장단점·찬반 비교에 사용.

::: htmlart balance
* 도입 찬성
  - 비용 절감
  - 자동화
  - 확장성
* 도입 반대
  - 학습 비용
:::

---

## compare — 좌우 동등 비교 (Issue208)

* 최상위 정확히 2개(좌·우). 라벨 형식 `**헤드라인** / 부제` (`/`로 분리, 부제 생략 가능).
* balance(시소·무게) 와 달리 좌우 동등 병렬. 대비·구분에 사용.

::: htmlart compare
* **도구의 영역** / 배워도 효율이 떨어지는 것
  - 클로드 Code, 터미널, git, API 설정
  - MCP 서버 구성, 코드 디버깅
  - 스킬, 에이전트, 자동 최적화
* **사고의 영역** / 배워서 가치를 높이는 것
  - 클로드와 채팅으로 좋은 결과 만들기
  - 실무 작업을 AI+나의 영역으로 구분하기
  - 생각의 외주화 습관 버리기 (인지 주권)
  - 내 생각/의도를 언어로 정의하기
  - HITL(AI + 사람 검수) 적용하기
:::

## explain — 중앙 명제 + 사방 풀이 (Issue211)

* 첫 항목 = 중앙 큰 강조 명제. 나머지 = 사방 풀이 phrase.
* radial(중심+스포크 박스)과 달리 박스 없이 텍스트만. 정의 확장·다관점 풀이에 사용.

::: htmlart explain
* Skill.md 이해하기
* 기본+커스텀
* 메모장에서 열리는 파일
* 마크다운 방식으로 작성
* 클로드가 참고하는 작업 지침
* 필요할 때 업로드해 사용
* 쟁여 놓고 꺼내 쓰는 자산
:::
