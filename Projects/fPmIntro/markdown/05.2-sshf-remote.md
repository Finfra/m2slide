# sshf & 원격 서버 — 로컬과 동일한 워크플로우

* **이게 없으면 겪는 불편**: 서버 IP·접속 정보를 외우고, 로컬과 원격에서 작업 방식이 달라져 매번 다시 적응함
* `sshf`는 서버도 **번호·이름**으로 접속하고, 원격에서도 fPM을 그대로 씀

::: cards
* **sshf**
  - 서버 목록 표시
* **sshf 3**
  - id로 접속
* **sshf gpu1**
  - 이름으로 접속
:::

# 서버 레지스트리 → 이름으로 접속

::: columns
:::: {.column width="40%"}
* 서버 목록은 `___pm`의 `Servers.md`에 번호·이름·호스트로 등록됨 (프로젝트 레지스트리와 같은 방식)
* `cdf 1`(→ ___pm) → `Servers.md` 확인 → `sshf jm2` → 원격 접속 성공 흐름
* 접속 후 프롬프트가 `nowage@jm2`로 바뀜 — IP·포트를 한 번도 타이핑하지 않음

# 한 번 익히면 어디서나 — graceful degrade

::: htmlart compare
* **로컬 macOS** / 풍부한 지원
  - iTerm2 분할
  - Finder 열기
  - 클립보드 복사
* **원격 Linux** / 자연스러운 축약
  - 기본 cd / ssh
  - 없는 기능은 자동 축약
  - 같은 명령 그대로 동작
:::

* 원격 서버에서도 `cdf` 네비게이션·hub·작업 흐름이 **로컬과 동일**하게 동작함 — 재학습 비용이 없음

> Before → After: "서버마다 다른 방식"에서 "로컬에서 익힌 그대로 원격에서도"로 바뀜

# 원격·LAN 접속 구성

::: columns
:::: {.column width="40%"}
* hub Settings의 **Advanced** 탭에서 원격·모바일 접속을 구성함
* **bind host**에 LAN IP(`192.168.0.17`)를 더하면 같은 네트워크의 다른 기기가 hub에 접속함
* **advertise host**(`jm4.local`)는 QR·링크 노출 호스트, **ssh remote alias**는 원격 접속 별칭
* 이 설정으로 `/qr` 모바일 열람과 `sshf` 원격 접속이 한 hub로 묶임
