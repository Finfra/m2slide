# Claude Code 단독의 고충 → fPM이 해결하는 방식

* 이 슬라이드가 데크 전체의 **필요성 훅(hook)**임 — "맞아, 나도 이거 불편했어"를 먼저 느끼면 나머지 기능이 자연스럽게 이해됨
* Claude Code는 강력하지만 아래 **전제** 위에 설계됨. 그 전제와 **실제 작업**의 간극이 고충의 원인임

::: htmlart compare
* **Claude Code 단독** / 전제
  - 한 세션
  - 한 프로젝트
  - 한 채팅창
* **실제 작업** / 현실
  - 여러 프로젝트
  - 장시간·반복
  - 여러 창을 넘나듦
:::

---

# Before → After 한눈에 비교

| 상황          | Claude Code 단독       | fPM 적용 후             |
| :------------ | :--------------------- | :---------------------- |
| 결과 확인     | 채팅에서 스크롤·재탐색 | HTML 문서로 렌더·재열람 |
| 장시간 작업   | 끝날 때까지 대기       | 대시보드 실시간 진행률  |
| 프로젝트 이동 | 경로 암기 + `cd`       | `cdf 11` 즉시 이동      |
| 의존 작업     | 순서 수동 관리         | `depends`로 자동 위임   |
| 작업 공간     | 창 3개 오감            | VSCode 한 화면          |
| 원격 서버     | IP·접속 정보 암기      | `sshf gpu1` 이름 접속   |

* 핵심은 **"기억·전환·대기"라는 반복 비용을 fPM이 대신 처리**한다는 점임

# 무엇이 본질적으로 달라지나

::: htmlart arrow
* 휘발
  - 채팅에 흘러감
* 영속
  - 파일·링크로 남아 재열람·공유
* 대기
  - "언제 끝나지?"
* 관측
  - 진행률 실시간
* 암기
  - 경로·서버 외우기
* 지목
  - 번호·이름 한 단어
:::

> fPM은 새 기능을 배우는 도구가 아니라, **반복 비용을 없애 Claude Code에 집중하게 하는** 도구임
