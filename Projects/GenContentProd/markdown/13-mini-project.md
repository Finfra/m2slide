# 10. 미니 프로젝트 — Prompt-to-Publish 5단계

## 미니 프로젝트 개요 — Prompt-to-Publish 5단계



* 시간: 60분 (체크포인트 6개 × 약 10분)
* 주제: 각자 관심사 1개 (업무·취미·관심 분야 자유)
* 산출물: 출판 가능한 문서 1편 (DOCX 또는 PDF)
* 5단계 흐름
  * ① 주제 선정 → ② Markdown 초안 → ③ Diffusion 이미지 → ④ Mermaid·Excalidraw 다이어그램 → ⑤ Obsidian 정리 → ⑥ Pandoc 출력


---

## 5단계 산출물 명세

* ① 주제: 1줄 — ex) “재택근무 효율화 팁 5선”
* ② Markdown 초안: ~500자, Frontmatter + 본문 + 목록
* ③ 시각 자산 1: Diffusion 이미지 1~2장 (표지·일러스트)
* ④ 시각 자산 2: Mermaid 또는 Excalidraw 다이어그램 1~2장
* ⑤ Obsidian 정리: Vault에 노트 1개 + 백링크 1건 + 태그 2개
* ⑥ Pandoc 출력: DOCX 또는 PDF 최종 파일 1개
* 단계별 시간: 약 10분 × 6 = 60분 — 시간 초과 시 ④ 또는 ⑤ 생략 가능

---

## ✅ 체크포인트 1 — 주제 선정 (10분)

* 조건: 본인이 60분 안에 풀어낼 수 있는 작은 주제 1개 확정
* 권장 범위: 글 1편으로 끝낼 수 있는 단일 주제 (대제목 1줄로 표현 가능)
* 비추천: “AI의 미래” 같은 거대 주제 — 60분에 불가능
* 추천 형식: “(대상) + (행동) + (수치)” — ex) “주니어 개발자 코드 리뷰 5가지 습관”
* 보조강사 활용: 주제 결정 못 한 청중에게 1:1 코칭 1분씩

---

## ✅ 체크포인트 2 — Markdown 초안 (10분)

* Part1 6대 패턴 활용 — Role + Constraint + Format 조합 권장
* 프롬프트 예: “당신은 [주제] 전문가입니다. 500자 분량 Markdown 형식으로, H1 1개·H2 3개·목록 5개 이상 포함해 작성하세요.”
* 결과를 본인 .md 파일에 붙여넣기 → 본인 시각으로 1줄 직접 수정
* AI 출력 100% 신뢰 금지 — 검토 1줄이 통과 조건
* 글 분량: 본문만 500~800자 (장황 금지)
* ✅ 통과 조건: Frontmatter + H1 + H2 3개 + 목록 5개 이상 충족 + 직접 수정 1줄 흔적

---

## ✅ 체크포인트 3 — Diffusion 이미지 (10분)

* Part1 Diffusion 항목에서 익힌 4요소 프롬프트 사용 (주체·스타일·구도·라이팅)
* 도구 자유: ChatGPT Image / Gemini Imagen / Bing Image Creator / Midjourney
* 표지 이미지 1장 + (선택) 본문 일러스트 1장
* 생성된 이미지를 .md 파일과 같은 폴더에 저장 → `![이미지 설명](image.png)` 으로 삽입
* 라이선스 주의: 상업 활용 여부는 도구마다 다름, 본 실습은 학습용

---

## ✅ 체크포인트 4 — Mermaid·Excalidraw 다이어그램 (10분)

* Part1 Mermaid·Excalidraw 항목 그대로 적용
* Mermaid 권장 (텍스트만으로 다이어그램) — 청중이 더 빠르게 끝냄
* 프롬프트 예: “[주제]의 단계를 flowchart로 그릴 Mermaid 코드를 작성하세요. A→B→C 흐름으로.”
* VSCode Mermaid Preview 확장으로 즉시 렌더 확인 → .md 본문에 mermaid 코드 블록으로 삽입
* Excalidraw 선택 시 노트에 임베드 (Obsidian Excalidraw 플러그인 활용)
* ✅ 통과 조건: .md에 Mermaid 코드 블록 1개 이상 + 미리보기에서 다이어그램 정상 렌더

---

## ✅ 체크포인트 5 — Obsidian 정리 (10분)

* 본인 Markdown 파일을 Obsidian Vault로 이동(복사)
* Vault 내에 새 노트 1개 추가 — “참고 자료” 또는 “관련 노트” 역할
* 두 노트 간 `[[..]]` 양방향 링크 1건 생성
* 태그 2개 추가 — ex) `#lec` `#{주제키워드}`
* 그래프 뷰에서 노드 2개·엣지 1개 확인
* ✅ 통과 조건: Vault에 노트 2개 + 백링크 1건 + 태그 2개 + 그래프 뷰 확인

---

## ✅ 체크포인트 6 — Pandoc 출력 (10분)

* 본 미니 프로젝트의 최종 산출 단계
* 명령: `pandoc {본인파일}.md -o {본인파일}.docx` 또는 `.pdf`
* 이미지 경로 오류 시 작업 디렉토리 확인 — `cd` 위치를 .md·이미지가 같은 폴더로 맞춤
* PDF 변환 실패 시 HTML 우회: `pandoc {파일}.md -o {파일}.html` → 브라우저 열기 → 인쇄 → PDF로 저장
* 완성 후 옆 사람과 1분 비교 — 표지·이미지·다이어그램 모두 정상 표시 확인
* ✅ 통과 조건: DOCX 또는 PDF 파일 1개 생성 + 본문·이미지·다이어그램 모두 정상 렌더링

---

## 🙋 진행 중 도움 요청 — 보조강사 호출 절차

* 1차: 옆 사람에게 1분 질문 — 동일 단계라 즉시 응답 가능성 높음
* 2차: 본인 단계 통과 조건 미달 5분 경과 시 손들기
* 3차: 보조강사 1명이 1:1 응대 (강사는 전체 흐름 유지)
* 자주 막히는 지점: ② Markdown 형식 / ⑥ Pandoc 작업 디렉토리 — 이 두 곳에 보조강사 주의 집중
* 시간 부족 시 단계 ④ 또는 ⑤ 1개 생략 허용 — ⑥ 출판 완성은 필수

---

## 중간 체크포인트 — 30분 경과 확인

* 30분 시점에서 진행 평균 확인
* 평균 ③ 이상 도달 → 정상 페이스, 계속 진행
* 평균 ② 이하 → 단계 ④ 생략 권고, ⑤·⑥에 집중
* 진행이 빠른 청중에게 추가 과제: Smart Connections로 본인 노트 Q&A 시도
* 짧은 호흡(2분) — 자리에서 일어나 스트레칭 권장
* 강사 메모: 30분 시점 = 페이싱 결정 분기점. 손들기 응답 5건 이상이면 같은 지점에서 막힌 것 — 전체 안내 1분 필요

---

## (선택) 발표 진행 방식 — 1인 2분 × 10명 샘플

* 시간: 20분 (발표 12분 + 리뷰 8분)
* 형식: 1인 2분 발표 — 6분간 자원자 1차 → 6분간 강사 지명 2차
* 발표 내용: 주제 1줄 + 산출물 화면 공유 (DOCX 또는 PDF 열기) + 어려웠던 점 1줄
* 청중 30명 중 10명 샘플 — 전체 발표는 시간 미달
* 발표 못 한 청중은 채팅·포스트잇으로 사후 공유
* 강사 메모: 자원자가 없으면 진행이 빠른 청중을 사전에 지명. “처음 1명만 어렵지, 그 다음은 술술”
* Q&A 슬롯: 2분 — 미니 프로젝트 진행 도중 즉문즉답

---

## 🙋 직접 따라 하세요 — 상호 리뷰

1단계: 옆 사람과 산출물 교환 (DOCX/PDF 화면 공유 또는 출력물 교환)

2단계: 4축 기준으로 한 줄씩 코멘트 작성 (총 4줄)

3단계: 가장 좋았던 1축 + 개선 1축 표시 — 포스트잇 또는 채팅

4단계: 작성자에게 코멘트 전달 + 1분 대화

✅ 통과 조건: 4줄 코멘트 작성 + 옆 사람과 교환 완료

💡 강사 메모: 코멘트는 “구체적 사실 + 본인 느낌” 권장. “좋아요/싫어요” 단답 금물.
