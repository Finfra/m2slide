## Usage scenarios

---

## Repeatedly Revised Lecture and Training Material

* When one lecture is reused across many cohorts and **only parts get revised each time**
* Because it's Markdown, you can **track what changed** by diffing against earlier versions
* Chapter-based structure means **reordering a lecture = reordering links in the TOC file**

---

## Technical Talks and Conference Sessions

* Especially good for talks packed with code blocks, diagrams, and math
* The presentation slides can also be **distributed as a reading e-book (EPUB)** — no separate handout needed after the talk
* You can **version-control the material alongside code** in a repository

---

## Internal Docs and Onboarding Material

* Docs edited by many people benefit from a **text format with no merge conflicts**
* The TOC structure (chapter mode) becomes the doc structure, so **management stays clean as docs grow**
* Static HTML output means it **deploys anywhere as-is** — internal web servers, GitHub Pages, and more

---

## Migrating PowerPoint Assets to Markdown

* There's a path to **reverse-convert existing `.pptx`** into a Markdown project — text, color, and structure carry over automatically
* From then on you never go back to PPT and **keep maintaining in the Markdown authoring flow**
* Conversely, there's also an export path from Markdown to PowerPoint, so you can **hand off PPT to those who require it**

---

## When You Must Ship Slides and an E-book Together

* Rebuilding the same content as "slides to show" and "a book to read" is duplicate work
* From one Markdown source, m2slide **produces HTML slides and EPUB together**
* Right after a talk you can hand attendees a tidy e-book

---

## When Another Tool May Be a Better Fit

* If free drag-and-drop placement and pixel-level design tuning are the point, PPT/Keynote fit better
* Teams averse to Markdown syntax itself may face an adoption barrier
* m2slide shines most in **structured, repeated authoring**
