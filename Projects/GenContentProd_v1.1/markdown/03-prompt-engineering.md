## 프롬프트 엔지니어링이란?

::: cards
* **정의**
  - 프롬프트 엔지니어링은 사용자의 질문이나 명령(프롬프트)을 최적화하여, 인공지능 모델로부터 원하는 응답을 효과적으로 얻어내는 과정임.
* **목적**
  - AI의 응답 정확도를 높이고, 사용자의 의도에 맞는 결과를 얻기 위해 설계된 프롬프트를 생성하는 것임.
:::

* 프롬프트는 모델에게 학습 데이터에서 추출한 지식을 활용하여 원하는 결과를 생성하도록 지시하는 역할을 함


---

## 프롬프트 엔지니어링이란?

::: cards
* **01. 기술**
  - AI 모델에게 원하는 결과를 얻도록 지시하는 명령어(프롬프트)를 만드는 기술
* **02. 과정**
  - AI 모델의 성능을 극대화하고 원하는 텍스트, 코드, 이미지 등을 생성하도록 최적화하는 과정
* **03. 방법**
  - 언어 기술과 창의적인 표현을 결합하여 AI와 효과적으로 소통하는 방법
:::

* AI 모델은 학습 데이터를 기반으로 작동하며, 잘 설계된 프롬프트는 모델 성능에 직접 영향을 줌
* 프롬프트 엔지니어링은 반복적인 실험·최적화 과정임

## 프롬프트 엔지니어링의 원리

::: cards
* **AI 모델은 학습 데이터를 기반으로 작동함**
  - 프롬프트는 모델에게 학습 데이터에서 추출한 지식을 활용하여 원하는 결과를 생성하도록 지시하는 역할을 함
* **프롬프트는 명확하고 구체적이어야 함**
  - 모델은 모호하거나 불분명한 지시를 이해하지 못할 수 있음
* **프롬프트는 모델의 성능에 영향 줌**
  - 잘 설계된 프롬프트는 모델의 정확성과 효율성을 높일 수 있음
* **프롬프트 엔지니어링은 반복적인 과정임**
  - 원하는 결과를 얻기 위해서는 다양한 프롬프트를 실험하고 최적화해야 함
:::

## 프롬프트 엔지니어링의 6대 기본 요소

::: cards
* **Persona (페르소나)**
  - AI가 취할 인격이나 역할을 정의함.
* **Context (맥락)**
  - 프롬프트가 제시되는 상황이나 배경 정보를 명시함.
* **Example (예시)**
  - 원하는 응답 형식이나 내용에 대한 구체적 예시를 제공함.
* **Form (형식)**
  - 응답받고자 하는 정보의 형태를 지정함 (예: 목록, 요약, 상세 설명).
* **Tone (톤)**
  - AI 응답의 어조나 성격을 지정함 (예: 친절한, 전문적인, 유머러스한).
* **Task (과제)**
  - AI에게 요청하는 구체적인 작업이나 목표를 명시함.
:::


---

## 기본 요소의 실제 예

::: cards
* **여행 일정 생성**
  - Persona: 여행 컨설턴트
  - Context: 2주간의 유럽 여행
  - Example: 방문 도시, 추천 여행지, 예산 계획
  - Form: 단계별 여행 일정표
  - Tone: 친절하고 상세한
  - Task: 여행 일정과 예산 계획 제공
* **오류 해결 가이드**
  - Persona: IT 지원 팀
  - Context: 소프트웨어 오류 메시지 해결
  - Example: 오류 코드와 가능한 해결책
  - Form: 단계별 문제 해결 가이드
  - Tone: 전문적이고 명확한
  - Task: 오류 해결을 위한 지침 제공
* **제품 홍보 콘텐츠**
  - Persona: 마케팅 전문가
  - Context: 새로운 제품 출시
  - Example: 제품 특징, 타겟 고객, 시장 위치
  - Form: SNS 게시물, 블로그 포스트
  - Tone: 설득력 있는, 창의적인
  - Task: 제품 홍보 콘텐츠 작성
:::

## Zero-shot — 예시 없이 바로 묻기

* **정의**: 예시·맥락 없이 작업 지시만 1줄로 던지는 방식
* **적합 시나리오**: 단순 요약·번역·분류 등 모델이 이미 잘 아는 작업
* **한계**: 출력 형식·톤이 모델 마음대로 → 일관성 부족
* **예시 프롬프트**: “다음 문장을 한 줄 요약: {본문}”
* **권장 사용처**: 빠른 초안·아이디어 발산 단계

---

## Few-shot — 예시 2~3개로 톤 잡기

* **정의**: 입력→출력 예시를 2~3쌍 제시하고 새 입력 요청
* **효과**: 모델이 예시의 형식·톤·길이를 모방함 → 일관성 확보
* **적합 시나리오**: 일관된 양식의 출력 필요 (이메일·요약·분류 라벨링)
* **예시 구조**: 예시1: {입력1} → {출력1} / 예시2: {입력2} → {출력2} / 질문: {새 입력}
* **주의**: 예시의 편향이 결과에 그대로 전이됨 — 좋은 예시가 핵심

![Few-shot — 예시 2~3개로 톤 잡기](img/GenContetntsProd_v10_2.png)

## 🙋 Few-shot 실습 — 직접 따라 하세요



* 작업: 영어 한 문장을 한국어로 번역하는 Few-shot 프롬프트 작성
* 절차:
  * Step 1: 시스템에게 “당신은 한영 번역기” 역할 부여
  * Step 2: 예시 3쌍 제시 (영→한, 격식체로 통일)
  * Step 3: 새 영어 문장 1개 입력 → 결과 확인
  * Step 4: 예시 톤을 반말로 바꿔 같은 입력 → 결과 차이 비교
* 평가: 예시 톤·문체와 새 결과가 일치하는지 확인
* 시간: 5분


---

## Chain of Thought — 단계별 추론 유도

* **정의**: “단계별로 생각해라(Let’s think step by step)”라는 지시로 모델이 사고 과정을 풀어쓰게 함
* **효과**: 수학·논리·복합 추론에서 정답률 20~40% 상승 (벤치마크 보고)
* **적합 시나리오**: 다단계 계산·인과 분석·요건 분해
* **예시 프롬프트**: “다음 문제를 단계별로 풀어라. 1단계: … / 2단계: …”
* **비개발자 응용**: 일정 산정·예산 분할·후보 비교 의사결정에 그대로 사용 가능

---

## 🙋 CoT 실습 — 직접 따라 하세요



* 작업: “회식 장소 후보 3곳 중 1곳을 선정하라”를 CoT로 풀기
* 절차:
  * Step 1: 후보 3곳·평가 축 4개(가격·위치·메뉴·분위기) 입력
  * Step 2: “단계별로 비교한 뒤 1곳을 선정하라”고 지시
  * Step 3: 사고 과정이 출력되는지 확인
  * Step 4: CoT 지시 없이 같은 입력 → 결과 차이 비교
* 평가: 단계별 비교 표·이유 설명이 자연스럽게 등장하는지 확인

## Role Prompting — 역할 부여



* 정의: “당신은 ○○ 전문가다”라고 역할을 부여하여 응답 톤·전문성을 통제
* 효과: 동일 질문도 역할에 따라 답변 깊이·용어가 달라짐
* 적합 시나리오: 분야 자문·검수·교육용 설명
* 예시 역할:
  * “당신은 노련한 카피라이터” → 헤드라인 톤
  * “당신은 깐깐한 코드 리뷰어” → 비판적 검수
  * “당신은 초등학생도 이해할 수 있게 설명하는 선생님” → 쉬운 비유
* 주의: 역할이 너무 길면 모델이 형식만 흉내 — 핵심 1~2줄로 압축


---

## Constraint·Format — 출력 형식 통제



* 정의: 응답의 길이·구조·포맷·금지어를 명시적으로 제약하는 방식
* 효과: 후가공 작업 절감 — Markdown 표·JSON·번호 목록 등 바로 사용 가능
* 자주 쓰는 제약:
  * 길이: “100자 이내”, “5문장으로”
  * 구조: “Markdown 표로”, “JSON 객체로 keys: title, summary, tags”
  * 금지: “이모지 사용 금지”, “한자 사용 금지”
* 조합 권장: Role + Constraint + Format을 같이 묶어 사용


---

## Self-Consistency·Self-Refine



* Self-Consistency: 같은 질문을 N회 반복 → 다수결로 최종 답 채택
  * 적합 시나리오: 수치 추정·분류 정확도가 중요한 작업
* Self-Refine: 1차 답변 → “이걸 더 좋게 다시 써라” 자기 수정
  * 적합 시나리오: 글쓰기·기획서 초안 다듬기
* 핵심 차이: SC는 “다수결”, SR은 “되돌아보기”
* 비용: 호출 N배 증가 — 중요한 결정에만 선택적 사용
* 도구 팁: Claude·ChatGPT 채팅에서 “이 답변을 더 정확하게 다시 써줘”가 Self-Refine

## 🙋 패턴 조합 실습 — 직접 따라 하세요



* 작업: 신제품 출시 보도자료 초안을 Role + Constraint + Format 조합으로 작성
* 절차:
  * Step 1: Role — “당신은 노련한 IT 기자”
  * Step 2: Constraint — “150자 이내, 이모지 금지”
  * Step 3: Format — “헤드라인 1줄 + 본문 3문단 (Markdown)”
  * Step 4: 입력 — 가상의 제품 1개 (이름·기능 1줄)
  * Step 5: Self-Refine — 1차 결과에 “더 임팩트 있게 다시 써줘”
* 평가: 헤드라인·본문 구조가 지시대로 나왔는지, 재작성 결과가 개선되었는지

## Q&A + 6대 패턴 정리



* 6대 패턴 한 줄 정리:
  * Zero-shot: 빠른 초안
  * Few-shot: 톤·양식 통일
  * CoT: 다단계 추론
  * Role: 전문성·톤 부여
  * Constraint·Format: 후가공 절감
  * Self-Consistency·Refine: 품질 검증·재작성
* 실무 권장: 시작은 Role + Constraint + Format 3종 조합으로 충분
* 어려운 작업일 때 CoT 추가, 양식 일관성이 중요할 때 Few-shot 추가
