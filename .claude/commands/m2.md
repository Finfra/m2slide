# /m2 커맨드

m2slide authoring-pipeline 단계 1~9의 단일 진입점. Git-style subcommand 패턴으로 신규 프로젝트 시작·중단 작업 재개·부분 단계 실행·상태 조회를 동사 1개로 표현.

SSOT 설계: [`_doc_arch/authoring-pipeline.md`](../../_doc_arch/authoring-pipeline.md) "작업 진입점 — /m2 라우터 커맨드" 섹션.
위임 대상 agent: [`agents/authoring-pipeline.md`](../agents/authoring-pipeline.md).

## 사용법

```
/m2 <subcommand> [<name>] [--from N] [--to M]
```

## Subcommand 일람

| 커맨드                              | 동작                                                | 위임                                                |
| :---------------------------------- | :-------------------------------------------------- | :-------------------------------------------------- |
| `/m2 init <name>`                   | 신규 프로젝트 골격 + 단계 1 시작                    | `/new-project` (글로벌) → `info-filler` agent       |
| `/m2 continue <name>`               | resume 지점 자동 감지 → 단계 9까지                  | `authoring-pipeline --from-stage <auto>`            |
| `/m2 continue <name> --from N`      | 단계 N부터 단계 9까지                               | `authoring-pipeline --from-stage N`                 |
| `/m2 run <name> --from N --to M`    | 단계 N~M 범위만 실행                                | `authoring-pipeline --from-stage N --to-stage M`    |
| `/m2 run <name> --to M`             | resume 지점부터 단계 M까지                          | `authoring-pipeline --to-stage M` (from auto)       |
| `/m2 build <name>`                  | 단계 8(slide HTML 빌드)만 실행                      | `./m2slide.sh <name>` 직접                          |
| `/m2 status <name>`                 | 현재 어느 단계까지 완료됐는지 표시 (실행 안 함)     | resume 감지 함수만 호출                             |
| `/m2 list`                          | `Projects/*` 목록 + 각 진행 상황                    | 모든 프로젝트에 resume 감지 적용                    |
| `/m2 --help`                        | subcommand 일람 + 예시                              | —                                                   |

## 인자 파싱

1. **첫 토큰 = subcommand**: `init`/`continue`/`run`/`build`/`status`/`list`/`--help`
2. **두 번째 토큰 = `<name>`**: `list`/`--help` 제외 모든 subcommand에서 필수
3. **나머지 토큰**: `--from N`, `--to M` 파싱 (`continue`/`run`만 의미 있음)
4. **알 수 없는 subcommand**: `--help` 표시 후 종료
5. **`<name>` 누락** (필수인 subcommand): `Projects/` 목록 표시 + `/m2 list` 또는 `/m2 init <name>` 권장

## Resume 자동 감지 알고리즘

`Projects/<Name>/` 산출물 존재 여부로 다음 미완 단계 추론. `continue`/`status`/`run --to M` (from 미지정) 세 경우에 공유.

| 검사 순서 | 조건 (해당 시)                                                              | resume 단계 |
| :-------: | :-------------------------------------------------------------------------- | :---------: |
| 1         | `Projects/<Name>/Info.md` 없음                                              | 1           |
| 2         | `Projects/<Name>/refs/` 없음 또는 비어있음 또는 `refs/index.md` 없음        | 2           |
| 3         | `Projects/<Name>/markdown/AGENDA.md` 없음 **and** `Projects/<Name>/<Name>.md` 없음 | 3      |
| 4         | 위 단계 통과했으나 슬라이드 `.md` 본문이 frontmatter only (헤더·본문 없음)  | 4           |
| 5         | `.md` 내 `![](./img/...)` 참조 중 하나라도 파일 부재                        | 5           |
| 6         | `Projects/<Name>/*.ppt.md` 또는 `markdown/*.ppt.md` 없음                    | 6           |
| 7         | `*.ppt.md` 내 `{{slotName}}` placeholder 잔존 (slot 미주입)                 | 7           |
| 8         | `Projects/<Name>/slide/*.html` 없음                                         | 8           |
| 9         | `Projects/<Name>/<Name>.txt` 없음 **or** `<Name>.tts.txt` 없음              | 9           |
| 10        | 모두 존재                                                                   | "complete"  |

* 단일 페이지 vs 챕터 모드 구분: `markdown/AGENDA.md` 있으면 챕터 모드, 없으면 single 모드. 검사 경로 달라짐
* "frontmatter only" 판정: `.md` 파일에서 두 번째 `---` 이후 줄 수 < 3
* `complete` 시 사용자에게 "모든 단계 완료. 영상 렌더링은 `./run.sh <name>`" 안내

## 실행 절차

### Subcommand: `init`

1. `<name>` 추출
2. `Projects/<name>/` 이미 존재하면 에러 + `/m2 continue <name>` 권장 후 종료
3. 글로벌 `/new-project` 호출 (또는 직접 `mkdir -p Projects/<name>` + `Info.md` template 복사)
4. `info-filler` agent를 Task tool로 호출하여 대화형 `Info.md` 작성 시작
5. 완료 시 `/m2 continue <name>` 권장 안내

### Subcommand: `continue`

1. `<name>` 추출, `Projects/<name>/` 존재 검증
2. `--from N` 있으면 N 사용. 없으면 resume 감지 알고리즘 실행
3. resume == "complete" → 영상 렌더링 안내 후 종료
4. authoring-pipeline agent를 Task tool로 호출:
    ```
    Projects/<name>/ --from-stage <N> --to-stage 9
    ```
5. agent 결과를 사용자에게 그대로 전달

### Subcommand: `run`

1. `<name>` 추출, `Projects/<name>/` 존재 검증
2. `--from N` 없으면 resume 감지로 N 결정
3. `--to M` 없으면 M=9
4. N > M → 에러 후 종료
5. authoring-pipeline agent를 Task tool로 호출:
    ```
    Projects/<name>/ --from-stage <N> --to-stage <M>
    ```

### Subcommand: `build`

1. `<name>` 추출, `Projects/<name>/` 존재 검증
2. `Bash("./m2slide.sh <name>")` 호출
3. 빌드 후 검증: `slide/*.html` 존재 + 미치환 `{{` placeholder 없는지 확인
4. 실패 시 1회 재시도 후 사용자 보고 (Opus 4.7 실행 제약)
5. 성공 시 생성된 HTML 경로 안내

### Subcommand: `status`

1. `<name>` 추출, `Projects/<name>/` 존재 검증
2. resume 감지 알고리즘 실행
3. 결과 보고 (실행 안 함):
    ```
    프로젝트: <name>
    완료 단계: 1 → 2 → 3 → 4 (단계 5 미완)
    다음 단계: 5 (media-creater)
    재개 명령: /m2 continue <name>
    ```

### Subcommand: `list`

1. `Bash("ls -1 Projects/")` 호출하여 프로젝트 목록 수집
2. 각 프로젝트에 resume 감지 적용
3. 표 형식으로 보고:
    ```
    | 프로젝트          | 진행 단계 | 다음 단계        |
    | :---------------- | :-------: | :--------------- |
    | m2SlideStyle1_*  | 8 완료    | 9 (md→TXT)       |
    | LlmAndVibeCoding | complete  | (영상 렌더링)    |
    | graphify         | 1 진행중  | (info-filler 대화)|
    ```

### Subcommand: `--help`

본 문서의 "Subcommand 일람" 표 + "사용 시나리오"를 사용자에게 출력 후 종료.

## 에러 처리

| 케이스                            | 대응                                                             |
| :-------------------------------- | :--------------------------------------------------------------- |
| 알 수 없는 subcommand             | `--help` 출력 후 종료                                            |
| `<name>` 미존재 (init 제외)       | `/m2 list` 권장 메시지 + 종료                                    |
| `init`에서 `<name>` 이미 존재     | `/m2 continue <name>` 권장                                       |
| `--from N` 범위 밖 (N<1 or N>9)   | 에러 보고 후 종료                                                |
| `--to M` 범위 밖 (M<1 or M>9)     | 에러 보고 후 종료                                                |
| `--from N > --to M`               | 에러 보고 후 종료                                                |
| authoring-pipeline agent 실패     | agent 보고를 그대로 사용자에게 전달 (마스킹 금지)                |
| `m2slide.sh` 빌드 실패            | 1회 재시도 후 사용자 보고                                        |

## 결정 근거 보고 의무

사용자 입력 처리 후 한 줄로 결정 근거 보고:

```
ex) "subcommand=continue, name=graphify, resume 감지=단계 5 (media)"
ex) "subcommand=run, name=mylec, --from=3 --to=5 명시 사용"
ex) "subcommand=build, m2slide.sh 직접 호출"
```

## 사용 시나리오

### 신규 프로젝트 시작

```
/m2 init graphify
```

### 중단된 작업 이어 진행 (자동 감지)

```
/m2 continue graphify
```

### 단계 2부터 재시작

```
/m2 continue graphify --from 2
```

### 단계 3~5만 실행

```
/m2 run graphify --from 3 --to 5
```

### 슬라이드만 빌드

```
/m2 build graphify
```

### 진행 상황 확인

```
/m2 status graphify
```

### 전체 프로젝트 진행 상황

```
/m2 list
```

## 기존 진입점과의 관계

| 기존 진입점                          | `/m2` 매핑                              | 비고                                        |
| :----------------------------------- | :-------------------------------------- | :------------------------------------------ |
| `./m2slide.sh <name>`                | `/m2 build <name>`                      | shell wrapper 유지 — 라우터가 호출          |
| `./run.sh <name>` (videoMaker)       | (변경 없음)                             | 외부 영상 렌더링 — 본 SSOT 범위 밖          |
| `/new-project` (글로벌 SCAR)         | `/m2 init <name>` 내부에서 호출         | 글로벌 SCAR 변경 없이 위임                  |
| authoring-pipeline agent 직접 호출   | (보존)                                  | 부분 재실행 power-user용 — `--from`/`--to` |
| `/run <name>` (m2slide 로컬)         | `/m2 build <name>`과 유사               | 둘 다 유지 — `/run`은 Chrome 자동 실행 포함 |

## Claude 실행 지침

이 커맨드 호출 시:

1. `$ARGUMENTS`를 공백으로 분리하여 토큰화
2. 첫 토큰을 subcommand로 분기. 알 수 없으면 `--help` 출력
3. 결정 근거 한 줄 보고
4. 위 "실행 절차"의 해당 subcommand 항목 그대로 수행
5. resume 감지가 필요한 경우 알고리즘을 인라인으로 구현 (Bash + Read 조합으로 산출물 검사)
6. 위임 호출(Task tool 또는 Bash)의 결과를 그대로 사용자에게 전달

## Opus 4.7 실행 제약

* 검증 실패 시 1회 재시도 후 중단. 자동 우회 금지.
* authoring-pipeline agent의 사람 검토 체크포인트는 그대로 통과 (라우터에서 가로채지 않음).
* 사용자가 명시한 `--from`/`--to` 값은 그대로 전달 (라우터가 임의 조정 금지).
* 글로벌 SCAR(`~/.claude/`) 수정 요청은 즉시 거부 + 이슈 등록 안내.
